Welcome to Knome

Your own private AI at home - chat, tools, memory, characters and image generation. Everything runs on your computer. No cloud, no account, nothing leaves your machine.

Quick start

  1. Open a terminal in the Knome folder and run 
    ./Knome-start.sh
    The first time it sets everything up by itself - it asks you nothing. Later it just starts Knome and the image server.
  2. Put your models in place. Text models (.gguf, plus mmproj-*.gguf for vision) go in models/. Image models and their parts (diffusion model, text encoder, VAE) go in image-models/ - loose, in any order.
  3. Open the browser at http://127.0.0.1:8080, load a model in the Models window and chat. To make a picture press + → Create image or simply ask for one.

Install

Supported: Debian / Ubuntu (and Mint, Pop!_OS ...), Fedora, RHEL / Rocky / Alma / CentOS, Arch (and Manjaro, EndeavourOS ...), openSUSE / SLES. Other Linux works too - use the manual steps.

Automatic (recommended)

cd Knome.mi
./Knome-start.sh
  • Your Linux is detected and only the missing packages are installed (compilers, cmake, git, Python, Node.js, Vulkan headers, shader compiler, Mesa drivers).
  • The best build is chosen for you: CUDA (NVIDIA + toolkit), ROCm (AMD + ROCm), otherwise Vulkan (AMD, Intel, NVIDIA) or CPU when there is no GPU. Force one with ./install.sh --backend vulkan|cpu|cuda|rocm.
  • Builds the web UI, llama.cpp and stable-diffusion.cpp (bundled) and the Python tools.
  • CUDA and ROCm toolkits are huge and vendor-specific, so you install those yourself.

Options: --backend X, --no-image, --check (only report), --rebuild.

Manual install 
# 1. dependencies (pick your distro)
sudo dnf install gcc gcc-c++ make cmake git pkgconf-pkg-config curl openssl-devel python3 python3-pip nodejs22 nodejs22-npm vulkan-loader-devel vulkan-headers glslc spirv-headers-devel spirv-tools-devel glslang-devel
sudo pacman -S --needed gcc make cmake git pkgconf curl openssl python python-pip nodejs npm vulkan-icd-loader vulkan-headers shaderc spirv-headers spirv-tools glslang
sudo apt install build-essential cmake git pkg-config curl libssl-dev python3 python3-pip python3-venv nodejs npm libvulkan-dev glslc spirv-headers spirv-tools glslang-tools

# 2. web UI (Node 20.19+ or 22.12+)
cd llama.cpp/tools/ui && npm install && NODE_OPTIONS=--max-old-space-size=4096 npm run build && cd ../../..

# 3. llama.cpp  (-DGGML_VULKAN=ON | -DGGML_CUDA=ON | -DGGML_HIP=ON | nothing = CPU)
cmake -S llama.cpp -B llama.cpp/build -DCMAKE_BUILD_TYPE=Release -DGGML_VULKAN=ON
cmake --build llama.cpp/build --target llama-server --config Release -j$(nproc)

# 4. tools environment
cd core-tools && python3 -m venv venv && ./venv/bin/pip install "mcp>=2,<3" ddgs httpx beautifulsoup4 wikipedia && cd ..

# 5. image generation (optional)
git clone --recursive https://github.com/leejet/stable-diffusion.cpp stable-diffusion.cpp
cmake -S stable-diffusion.cpp -B stable-diffusion.cpp/build -DCMAKE_BUILD_TYPE=Release -DSD_SERVER_BUILD_FRONTEND=OFF -DSD_VULKAN=ON
cmake --build stable-diffusion.cpp/build --target sd-server --config Release -j$(nproc)

# 6. folders and start
mkdir -p models image-models memory slots
mkdir -p .knome-state && date +%s > .knome-state/setup-done
./start-knome.sh

Features

Chat & models

Local GGUF models through llama.cpp in router mode: load and unload in the Models window. Header shows model and context use.

Vision

Pick a vision projector per model (Models → Vision). Flat mmproj-*.gguf files are attached automatically.

Built-in tools

Memory, web search, Wikipedia, Python - plus any MCP server you add in Settings. Reasoning blocks, tables, code, a math keypad.

Library

Every picture and file from your chats in one place; jump back to the message it came from.

Memory & backups

Facts the AI keeps about you (Settings → Profile) and full, selectable backups (Settings → Import/Export).

Scheduled messages

Write now, send later (+ menu → Scheduled message). Projects and search across all chats.

Characters

Character cards with avatars and backgrounds, a Messenger layout (reactions, stars, search) and DeepMind mode where the AI texts like a person.

Looks

Light/dark themes, a modern or classic message bar, and experience modes: Clean & Minimal, Pro, or Free.

Images & video

Create pictures, edit your own, and let the AI choose size, steps and style. See the next section.

Images & video

Knome makes pictures with stable-diffusion.cpp. Because image models are big, Knome swaps them in and out for you: your chat model steps aside, the image model draws, then your chat model comes back. You do not have to manage anything.

Text model off→Image model on→Drawing→Image model off→Text model back

1. Create an image

Open the + menu and choose Create image - or just ask in plain words ("make me a cozy cabin at sunset, wide wallpaper").

2. Choose how - or leave it to the AI

When Create image is on, an Image chip appears next to Think, and an options bar opens above the message box. Every option says Auto (AI) by default, which means "you decide, AI". Set only what you care about:

OptionWhat it does
ModelWhich image model type to use (SDXL, Qwen Image, Z-Image, Flux ...).
Aspect1:1, 16:9, 9:16, 4:3, 3:4, 3:2, 2:3, 21:9.
SizeStandard, High, or Max for this model. Knome never asks a model for a size it cannot draw well.
QualityDraft (fast), Normal, High (slow). Turbo models keep their few steps.
StepsExact number of steps, if you want to be precise.
No hands needed. You can leave everything on Auto and just talk: "16:9, high quality, 40 steps, seed 7, no text". The AI writes the detailed prompt and sets size, steps, CFG, sampler, seed and the negative prompt. What you set in the bar always wins over the AI.

3. Watch it work

4. Edit your own pictures

Attach a picture and ask for a change ("make this night time", "colourful and better"). Edit-capable models (Qwen Image Edit, Flux Kontext ...) get your picture as a reference. Other models use it as the starting picture; the AI can set strength (small change ↔ big change).

5. Settings

Everything is detected and switched on by itself. If you want to change something: Settings → Profile → Image & video.

Adding image models

  1. Put the files into image-models/ - the diffusion model, its text encoder (LLM / CLIP), the vision projector if there is one, and the VAE. Order does not matter.
  2. Press Re-detect in the Models window (or restart). Knome recognises the model type from the file names and fills every part.
  3. Create an image. That is all.
How Knome connects to the image server (for the curious)

start-knome.sh builds .knome-state/sd-models/, a view of image-models/ made of hard links (the same files, no extra disk space), sorted into the folders the image server expects. Your text models are offered as text encoders too. Hard links are needed because the image server refuses symlinks that point outside its model folder - so keep models/ and image-models/ on the same disk. The UI talks to the server on port 1234 (/sdcpp/v1/...).

The image server is supervised: if it ever stops (for example the computer ran out of memory) it restarts by itself after three seconds.

Use your own stable-diffusion.cpp

stable-diffusion.cpp/ is a plain, untouched copy of upstream - Knome never edits it. Replace it any time:

rm -rf stable-diffusion.cpp
git clone --recursive https://github.com/leejet/stable-diffusion.cpp stable-diffusion.cpp
./Knome-start.sh        # notices sd-server is missing, builds it, starts everything

Low memory? Read this

Image models are heavy. A typical setup (a 6-bit 20B-class diffusion model, an 8B text encoder and a VAE) needs 13 GB or more just for the weights. Knome helps by:

  • unloading your chat model completely before the image model is loaded, and waiting a moment so the system can take the memory back;
  • starting the image server with memory-saving options (--mmap --vae-tiling);
  • letting the image server decide where each part lives (VRAM, RAM or streamed from disk) - slower, but it fits. On an 8 GB graphics card expect a few seconds per step up to a few tens of seconds.

What you can do: use a smaller quant (Q4 instead of Q6/Q8), a smaller text encoder, a smaller size, and close heavy programs while drawing. Set your own server options with SD_ARGS="--offload-to-cpu" ./Knome-start.sh.

Troubleshooting

"Cannot reach the image server"

It may have just stopped (often low memory). Knome restarts it by itself - wait a few seconds and try again. Details are in image-server.log.

"Model initialization failed"

Usually not enough memory, or a part that does not belong to this model type (wrong text encoder or VAE). Check Settings → Image & video, press Auto-detect models, and read the last lines of image-server.log.

A text model shows "Failed to load"

Image models do not belong in models/; put them in image-models/. Otherwise the cause is in the terminal where Knome runs (out of memory, or a llama.cpp too old for that model).

"0 files found" in the image section

Files must be inside Knome.mi/image-models/ and on the same disk as Knome.mi. Press Re-detect.

No GPU is used

For Vulkan install a Vulkan driver (mesa-vulkan-drivers, vulkan-radeon, vulkan-intel or the NVIDIA driver). Check with vulkaninfo --summary.

UI build: "JavaScript heap out of memory"

Close other programs and run ./install.sh --rebuild.

Updating with a patch

bash apply.sh /path/to/Knome.mi, then ./Knome-start.sh - it rebuilds the UI by itself.

Privacy

  • Knome runs on your computer. Chats, memory, images and settings stay in your browser and in your folders. There is no telemetry and no account.
  • The web search and Wikipedia tools only reach the internet when you use them.
  • Your personal folders (memory/, slots/, models/, image-models/) and runtime files (.knome-state/, image-server.log) are listed in .gitignore and are never published.
  • Before you publish your own copy run ./tools/check-before-publish.sh - it looks for personal paths, e-mail addresses and stray log files.
